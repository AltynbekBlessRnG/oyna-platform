# OYNA

Единая платформа для поиска и бронирования компьютерных клубов Казахстана.

## Приложения

- `apps/mobile` — мобильное приложение игрока на React Native + Expo.
- `apps/dashboard` — кабинет клуба на Next.js.
- `apps/api` — API на NestJS.
- `packages/contracts` — общие контракты данных.

## Запуск

```bash
pnpm install
pnpm dev:api
pnpm dev:dashboard
pnpm dev:mobile
```

API по умолчанию доступен на `http://localhost:4000/api`, кабинет — на `http://localhost:3000`.

## Сценарий бронирования

В мобильном приложении уже работает путь: клуб → дата и время → зона → места → проверка → подтверждение.

Основные API-методы:

- `GET /api/clubs/:clubId/zones`
- `GET /api/clubs/:clubId/availability?zoneId=standard&startAt=...&durationHours=3`
- `POST /api/bookings`
- `GET /api/bookings/:id`

API поддерживает PostgreSQL с транзакционной блокировкой мест; без `DATABASE_URL` автоматически включается временное in-memory хранилище.

## Пилотный режим

```bash
cp .env.example .env
pnpm db:up
pnpm db:seed
pnpm dev:api
pnpm dev:dashboard
pnpm dev:mobile
```

### PostgreSQL без Docker

Если Docker не установлен или нет прав root, локальную базу поднимает скрипт:

```bash
./scripts/local-postgres.sh install   # скачать PostgreSQL и создать кластер
./scripts/local-postgres.sh start     # запустить
./scripts/local-postgres.sh stop      # остановить
```

Бинарники кладутся в `~/.local/share/oyna/pgsql`, данные — в `~/.local/share/oyna/data`,
подключение совпадает с `.env.example`. Это вариант для разработки: клубу и production
нужен managed PostgreSQL.

При наличии `DATABASE_URL` API автоматически создаёт таблицы PostgreSQL. Без базы проект продолжает работать на временном in-memory хранилище.

- Вход по телефону: в development используется код `0000`.
- Клубы, зоны, цены и места хранятся в PostgreSQL и правятся в кабинете.
- Новые брони получают статус `pending`.
- Администратор подтверждает или отклоняет заявку в кабинете.
- Пользователь видит историю и может отменить будущую бронь.
- Интеграция клуба по умолчанию работает в ручном режиме.

## Клуб в кабинете

Каталог клубов лежит в базе, а не в коде. Загрузка и права администратора — через seed:

```bash
pnpm db:seed                                                   # демонстрационный каталог
pnpm db:seed -- --file=./clubs/example-club.json                # каталог реального клуба
pnpm db:seed -- --club=vertex-arena --admin-phone=+77011234567  # права администратора клуба
```

Файл каталога — массив объектов `{ "club": {...}, "zones": [...] }`; путь считается от `apps/api`,
шаблон лежит в `apps/api/clubs/example-club.json`. Повторный запуск обновляет данные, ничего не удаляя.

Дальше администратор входит в кабинет (`/login`) по своему номеру телефона тем же кодом, что и игрок,
и правит клуб, зоны, цены и количество мест на странице `/settings`.

Права раздаются по ролям:

- `platform_admin` — владелец платформы, видит все клубы и выдаёт доступы;
- `club_admin` с записью в `club_memberships` — управляет только своим клубом;
- `CLUB_ADMIN_KEY` — запасной ключ уровня платформы для демонстраций; в production работает, только если задан явно.

API проверяет принадлежность клуба на каждом административном запросе:
`GET /api/admin/me/clubs`, `GET|PATCH /api/admin/clubs/:clubId`, `PUT /api/admin/clubs/:clubId/zones`,
`GET /api/admin/clubs/:clubId/bookings`, `PATCH /api/admin/clubs/:clubId/bookings/:id/status`.

Зону с будущими бронями API не даст удалить или уменьшить по количеству мест.

## Вход по SMS

Код входа доставляет `SmsService`, канал выбирается переменной `OTP_PROVIDER`:

- `console` — код печатается в лог. Годится для разработки и контролируемой демонстрации.
- `mobizon` — [Mobizon](https://mobizon.kz/help/api-docs/message), нужен `MOBIZON_API_KEY`.
- `smsc` — [SMSC](https://smsc.kz/api/http/send/), нужны `SMSC_LOGIN` и `SMSC_PASSWORD`.

Имя отправителя задаётся `SMS_SENDER`. Если оператор выбран, но ключей нет, сервис
предупреждает в логе и остаётся на `console` — молча «терять» коды он не будет.

Запрос кода ограничен: не чаще одного раза в минуту и не больше пяти в час на номер.
Ограничение живёт в памяти процесса, поэтому при нескольких инстансах его нужно будет
перенести в базу или кэш.

В development код всегда `0000` и возвращается в ответе API. В production код случайный
и в ответе не приходит.

## Уведомления игроку

Когда клуб подтверждает, отклоняет или завершает бронь, игрок получает запись в центре уведомлений
(экран «Уведомления» в приложении) и push на зарегистрированные устройства через Expo.

Push-токен запрашивается после входа. В Expo Go начиная с SDK 53 remote push недоступны — нужен
dev- или production-билд и `extra.eas.projectId` в `app.json`; без этого уведомления остаются
видимыми внутри приложения.

## Проверка пилота

```bash
API_URL=http://localhost:4000/api CLUB_ADMIN_KEY=... ./scripts/pilot-smoke.sh
```

Скрипт проходит весь сценарий: каталог → вход игрока → бронь → защита кабинета → решение клуба →
уведомление игроку, и отменяет тестовую бронь в конце. Проверки правки клуба включаются через
`OYNA_SMOKE_MUTATE=1`. Для Windows остался `scripts/pilot-smoke.ps1`.

Перед встречей с клубом см. [чек-лист пилота](docs/PILOT_CHECKLIST.md) и [вопросы по интеграции](docs/INTEGRATION_QUESTIONS.md).

## Игровое сообщество

Платформа также включает первую версию социальных функций:

- общий канал Казахстана и городской канал Алматы для CS2, Dota 2 и VALORANT;
- сообщения через REST и Socket.IO namespace `/chat`;
- мини-профиль с аналитикой бронирований и турниров;
- подтверждаемую привязку Steam через OpenID;
- команды, приглашения и турниры single-elimination на 4/8/16/32 участника;
- заявки, резервный список, подтверждение результатов и споры;
- удаление аккаунта с семидневным периодом восстановления;
- центр уведомлений и регистрация Expo push-токенов.

Для Steam задайте `STEAM_RETURN_URL` и `STEAM_WEB_API_KEY`. Продажа и аренда игровых аккаунтов намеренно не поддерживаются.
