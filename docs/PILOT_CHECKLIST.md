# OYNA: чек-лист пилотного клуба

## До встречи

- Подготовить Android-телефон с тестовой сборкой OYNA.
- Запустить API, PostgreSQL и кабинет клуба.
- Проверить вход по коду `0000`, создание и ручное подтверждение брони.
- Создать отдельный тестовый admin key — не использовать пароль владельца клуба.

## Данные, которые нужны от клуба

- Название, адрес, часы работы и контакт ответственного.
- Система управления: SENET, SmartShell, LANGAME или другая.
- Список зон, тарифов и длительность минимальной сессии.
- Схема и нумерация ПК, характеристики каждой зоны.
- Правила отмены, опоздания и неявки.
- Способ подтверждения бронирований администратором.

## Технический доступ

- Только отдельный тестовый аккаунт с минимальными правами.
- Partner API / sandbox / Booking Portal, если система это поддерживает.
- Документация API и webhooks от официального представителя системы.
- Не передавать OYNA пароль владельца, кассира или доступ к рабочей кассе.

## Безопасный первый запуск

1. Неделя 1: теневой режим — OYNA создаёт заявку, администратор подтверждает вручную.
2. Неделя 2: реальные брони без онлайн-оплаты, лимит на несколько мест.
3. После сверки конфликтов: автоматическая синхронизация доступности.
4. Только после стабильной брони: депозит или онлайн-оплата.

## Метрики пилота

- Количество созданных и подтверждённых броней.
- Доля отмен и неявок.
- Среднее время ответа администратора.
- Конфликты мест и ручные исправления.
- Повторные визиты пользователей.
